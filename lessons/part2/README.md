# 第二篇 · Harness 的工具与记忆

> 目标：让 Agent 从"会说话"变成"会干活、记得事"。这两件事在 Harness 里分别叫**工具**和**session log**。

第一篇结束的时候，我们有了一个会胡说八道的假模型。它有两个致命缺陷：**什么都做不了**（不会调工具），以及**什么都记不住**（进程一退全忘）。

本篇一次解决这两个问题，然后再往下挖四层——失败怎么告诉模型、日志怎么变成模型看得见的历史、历史太长怎么办、进程重启后怎么把历史接上、以及谁在开口之前告诉模型它该是谁。

## 本篇的两条主线

**工具这条线**（10~13）讲的是"能力怎么递到模型面前"。Harness 里工具不是硬编码的几个函数，而是插件通过 `defineTool` 注册进一个注册表，模型按名字挑。这样加工具不用改 loop 一行代码——这也是第 08 课"能力接缝"的第一次实战。

**记忆这条线**（14~18）讲的是"事实存在哪、模型看见什么"。核心决定只有一句：**日志是唯一事实来源**。模型请求是从日志折出来的，压缩是往日志追加一条带替换标记的新记录，恢复是把日志读回来，提示词的变化也在日志里留痕。日志一行不改，所以任何时候都能重放、复盘、迁移。

这两条线在第三篇合流：一个真正的 Agent，就是"手里有工具、脑子里有日志、知道自己是谁、外加一个能跑的 loop"。
